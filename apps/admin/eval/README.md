# `apps/admin/eval/` — Semantic-search eval harness data

Committed operator data files for the local CLI eval harness. The
harness compares admin's hybrid-search results against a saved
baseline using pairwise LLM-as-judge so iteration on
`hybrid-search.service.ts` has a quantitative signal.

**Canonical docs:** `apps/admin/CLAUDE.md` → "Semantic search eval
harness" section. Read that first for architecture + operational
runbook. This file is just a quick reference for what's in this
directory.

## Files in this directory

```
apps/admin/eval/
├── baselines/{name}.json         # Frozen snapshots — commit these
├── synthetic-queries/{locale}.json  # Per-locale query lists — commit these
├── regressions.json              # Hand-edited adversarial set — commit this
└── calibration.json              # Hand-labeled judge-sanity cases — commit this
```

Per-run output is NOT in this directory — it lands at
`apps/admin/.tmp/eval/runs/{runId}.json` (gitignored).

Mastra-generated eval candidates are staged in Admin Postgres
(`search_eval_candidate`), not in this directory. They include source,
locale, provenance, source anchors, advisory judge summaries, and promotion
status, but they are not durable regression gates until a later sanitized
human-promotion flow moves selected cases into committed harness data.

### `baselines/{name}.json`

Frozen snapshot of `(queries, top-K results, content fingerprint)`
for a known-good state. Default name is `default`. Multiple named
baselines allowed if you want to compare against different reference
points. Re-baseline overwrites: `pnpm eval:search:rebaseline -- --yes`.

Don't hand-edit. Generated by the rebaseline command.

### `synthetic-queries/{locale}.json`

LLM-generated search queries per locale. ~50 queries each.
Committed so re-runs use the same query set against the same
baseline. Each file carries `schemaVersion`, `locale`, `generatedAt`,
`model`, `queries: string[]`.

Regenerate for one locale: `pnpm eval:search:regenerate-queries -- --locale=fr`.

Don't hand-edit individual files. If a locale's queries look broken
(judge consistently flags `both-irrelevant`), regenerate instead.

### `regressions.json`

Hand-edited adversarial set. Append an entry whenever you spot a
bad search result in the wild. The harness merges these with the
synthetic queries on every run, so each entry permanently joins the
test suite.

Schema:

```json
{
  "entries": [
    {
      "locale": "fr",
      "query": "espoir dans la souffrance",
      "notes": "should return Hope videos, not random ones",
      "addedAt": "2026-05-12T10:00:00Z",
      "addedBy": "nisal"
    }
  ]
}
```

`locale` and `query` are required; `notes`, `addedAt`, `addedBy` are
optional but please fill them in — it's the only context a future
operator has when this regression starts failing.

### `calibration.json`

10 hand-labeled cases run on every harness invocation to verify the
judge hasn't drifted. Three case types: obvious-A-wins (judge must
pick A), obvious-tie (identical lists), both-irrelevant (gibberish
query against unrelated content). PASS threshold ≥80%.

If the judge fails calibration consistently, switch
`OPENROUTER_JUDGE_MODEL` to a stronger model or pause iteration.
Don't lower the threshold to make calibration pass — that's lying
to yourself.

Each case carries `id`, `query`, `locale`, `listA`, `listB`,
`expected` (one of the six verdicts), and `rationale` explaining
what the expected verdict tests for.

## Quick command reference

```bash
cd apps/admin

pnpm eval:search:calibrate                          # ~30s sanity check
pnpm eval:search:rebaseline -- --yes                # capture first baseline (~15 min, ~$3-5)
pnpm eval:search:quick                              # iterate (~2 min, < $1)
pnpm eval:search                                    # full run (~15 min, ~$5-15)
pnpm eval:search --locale=fr                        # one locale only
pnpm eval:search:regenerate-queries -- --locale=fr  # rebuild one locale's synthetic queries
```

## What NOT to commit here

- `*.tmp` files (atomic-write artifacts from interrupted rebaselines).
- Anything under `apps/admin/.tmp/eval/runs/` (already gitignored).
- Raw exports of `search_eval_candidate` generated rows.
- Files containing real-user PII. Synthetic and adversarial queries
  should describe search intent, not quote actual user input.

## Cost guard rails

- Calibrate: ~$0.01 per run
- Quick (6 locales, ~300 queries): < $1
- Full (30 locales, ~1500 queries × 2 A/B-swap): $5–15
- Rebaseline (1500 searches + 30 synthetic-gen calls): $3–5

If a full run cost surprises you, check `report.cost` in the run
JSON — total tokens × Haiku 4.5 pricing constants are stamped in
`runner.ts:54-58` (2026-05-07).

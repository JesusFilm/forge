Does switching Core-sync to adminVideos fix the restrictViewPlatforms bug?

Question this demo answers: admin's Core-sync currently queries Core's public videos GraphQL field, sending header x-graphql-client-name: watch. Core's videos resolver silently applies filter.NOT = { restrictViewPlatforms: { has: "watch" } } whenever that header is a valid platform name — so any video Core has restricted for "watch" is excluded from every result set admin's sync ever sees, and admin's copy can never learn about (or correct itself for) that restriction. The proposed fix is switching the sync to Core's adminVideos field (same shape, no such filter, and admin's token already has the required publisher auth). This model lets you drive both mechanisms by hand and watch whether admin's copy ever converges with Core's, matching the real impulses-for-the-way-vertical row found in production (Core allegedly restricted, admin still shows restrict_view_platforms: {}).

✓ In sync — admin's copy matches Core's current restriction state.

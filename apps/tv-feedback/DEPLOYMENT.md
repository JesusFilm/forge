# Watch TV beta feedback deployment gates

The replacement service is deployed to Railway staging at `https://web-staging-920a.up.railway.app` (deployment `d118b25f-9aa5-49ad-b6f6-68ccd3066c75`, 2026-09-25). Production still uses the reviewed PR-to-main path.

1. Create one Railway web service from the Forge repository. Set Config-as-code Path to `/apps/tv-feedback/railway.toml`, provide a Railway HTTPS domain, and attach Redis. Set `REDIS_URL` and `FEEDBACK_BASE_URL` in the web service. Configure Redis persistence and no-eviction behavior; a lost/evicted grant must fail closed.
2. Set `RAILPACK_DEPLOY_APT_PACKAGES=ffmpeg` for the web service. The synchronous media processor requires both `ffmpeg` and `ffprobe` for video inspection. Set enough memory for one bounded 50 MB video plus transcoding; cap concurrent uploads before public testing.
3. Configure `FEEDBACK_SESSION_SECRET`, the existing Cloudflare Turnstile widget's public site key and private secret, and a dedicated Linear key restricted to the TV team. Set `TURNSTILE_HOSTNAMES` to the exact phone-form hostname for this deployment; do not allow localhost on a public backend. The widget action is `tv_feedback`. Enable Read, Create issues, and Write: Linear's `fileUpload` rejects a key without Write with `Invalid scope: write required`. Write also permits editing TV-team data, so retain the team restriction. Set team, [TV Beta Feedback](https://linear.app/jesus-film-project/project/tv-beta-feedback-0b56740fdc10/overview) project, and TV Beta Feedback issue-label IDs. The existing personal `JFP Linear` key is read-only and unsuitable. Do not put any private value in the TV app or QR.
4. Android: Play Console is linked to `jesus-film-stage` (`412620661851`). Set the server-only Google verification key, package, Play App Signing certificate digest, and approved build versions. First observe verdicts on Play-installed physical Android TV, then enforce. A native Android build is required for the Play Integrity module.
5. Apple TV: the native bridge and server validator use DeviceCheck, which is weaker than challenge-bound App Attest. Test DeviceCheck/App Attest support on physical TestFlight hardware. Enable `FEEDBACK_APPLE_DEVICECHECK_ENABLED=true` only after accepting the relay/reinstallation limits of DeviceCheck for this beta, or replace it with verified App Attest. Obtain the Apple DeviceCheck private key and set the team/key/bundle/build variables. Do not claim Apple TV requests have App Attest proof.
6. Submit a marked photo and a bounded MOV/MP4 from iPhone Safari and Android Chrome; confirm one issue with all selected media in the TV project. Exercise failed/ambiguous Linear responses, two-phone claim races, three daily reports, fourth rejection, and server/Redis restarts without duplicate issues or false success.
7. After the service passes staging tests, set the Railway HTTPS URL in the TV build environment and verify QR scans, expiry, focus restoration, and report delivery on physical Apple TV and Android TV.

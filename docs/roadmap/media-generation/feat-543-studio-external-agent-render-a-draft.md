## Problem

The connected agent requests a render of its current draft, checks progress after reconnecting, and retrieves scoped media access plus a human link to the exact output. Use existing footage without generated narration to prove this independently.

## What To Build

Approved acceptance criteria:

- [x] A narrowly authorized delegated request admits a render for an exact revision through the existing durable rendering service without impersonating a human reviewer.
- [x] Admission returns a durable attempt identity promptly; queued/running/succeeded/failed/stale outcomes remain readable across client disconnection.
- [x] Exact retries do not enqueue another render. Changed request bodies cannot reuse an accepted idempotency key.
- [x] Canonical capture and source materialization complete through the trusted broker; arbitrary fetch URLs and unverified media/code do not bypass existing containment.
- [ ] An operator can open the returned project/revision/render link and watch the exact generated bytes; a later project edit labels earlier output stale for approval.
- [x] Output byte access is short-lived and scoped; expired access can be refreshed through authentication without storing bearer URLs in project history.
- [x] Existing concurrency, execution timeout, cancellation/recovery, and immutable completion rules remain enforced. The tool grants no approval or publishing authority.

## Verification

Test boundary:

MCP request/status/read against canonical lifecycle and the contained render worker; loss/retry/stale-result cases.

Read actual package scripts before running targeted Vitest/DB tests, typechecks, lint and formatting. Use only guarded loopback databases and fake paid providers. Regenerate Admin SDL and admin-graphql together if Pothos changes. Record real-client evidence separately from transport probes.

## Constraints

Preserve expected-revision and idempotency semantics, human edits, scoped OAuth authority, and exact-render human approval. No paid provider calls, deployment, agent publication, automatic wakeups, or editor comments.

  contained execution; no revision edit or interactive actor is fabricated.

  to issued leases and retains referenced assets. Publication/staging select only
  the admitted successful lease; original authored revisions remain unchanged.

  `delegated.db.test.ts`, and `catalog.db.test.ts` pass (12 tests), covering stable retry, scope denial,

  membership revocation, lease fencing, immutable completion, and descriptor-source

## Problem

The web watch experience needs to treat human-authored subtitles and auto/AI-generated subtitles differently inside the video player UI. Today the player does not present that distinction clearly, which makes it harder to set the right expectations for subtitle quality, trust, and accessibility when generated tracks are available alongside editorial ones.

## Entry Points — Read These First

1. `apps/web/src/app/[slug]/page.tsx` — watch experience route that renders `/watch/[slug]` content
2. `apps/web/src/app/[slug]/[locale]/page.tsx` — localized watch experience route that should influence subtitle locale selection
3. `apps/web/src/lib/content.ts` — `GetWatchExperience` query and the typed watch data flow
4. `apps/web/src/lib/fragments/video-section.ts` — section fragment to extend with subtitle-track data from `videoRef`
5. `apps/web/src/components/sections/Video.tsx` — current video.js player implementation for standard video sections
6. `apps/web/src/components/sections/VideoHero.tsx` — hero player implementation that should stay aligned with subtitle behavior
7. `apps/cms/src/api/video-subtitle/content-types/video-subtitle/schema.json` — Strapi source of truth for subtitle fields and relations
8. `docs/roadmap/media-generation/feat-031-ai-video-enrichment-pipeline.md` — upstream dependency that creates the generated subtitle assets

## Grep These

- `GetWatchExperience\|experienceToMetadata` in `apps/web/src/lib/content.ts` — watch-page query and data mapping
- `videoRef\|streamingUrl\|VideoSection` in `apps/web/src/lib/fragments/` — section-level video data flow
- `videojs\|onPlayerReady\|playerRef` in `apps/web/src/components/sections/` — player lifecycle and control integration points
- `VideoSubtitle\|vttSrc\|aiGenerated\|primary` in `packages/graphql/src/graphql-env.d.ts` — existing generated subtitle contract
- `subtitles {\|vttSrc\|videoEdition` in `apps/cms/src/api/core-sync/gql/` — subtitle fields already flowing through sync queries

## What To Build

1. Extend the watch-page GraphQL payload so every player-capable video section can read subtitle tracks from the related `videoRef`, preferring VTT assets already generated by the enrichment pipeline.

   ```ts
   type SubtitleTrack = {
     id: string
     src: string
     label: string
     language: string
     isDefault: boolean
     isGenerated: boolean
   }
   ```

2. Update the shared video player UX in `apps/web/src/components/sections/Video.tsx` to register caption tracks with video.js and expose an obvious, accessible captions control when tracks exist.

3. Bring `apps/web/src/components/sections/VideoHero.tsx` to parity so hero players and standard players do not diverge on subtitle support.

4. Add simple selection rules for the initial track:
   - Prefer a primary subtitle when one exists.
   - Otherwise prefer a track whose language matches the route locale.
   - Otherwise leave captions off by default.

5. Add user-facing states around generated subtitles:
   - No empty subtitle chrome when a video has no tracks.
   - Clear labeling when tracks are AI-generated.
   - Graceful fallback when a track record exists but the VTT URL is missing.

## Constraints

- Reuse the existing watch routes and player components. Do NOT create a parallel video page just for subtitles.
- Prefer VTT subtitle assets already stored in CMS data. Do NOT build a transcript overlay or raw text renderer for this milestone.
- Do NOT hand-edit generated GraphQL output files. If query changes require generated type updates, regenerate them in the implementing PR.
- Keep captions support additive. Playback, mute, autoplay, and fullscreen behavior must remain unchanged when subtitles are absent.

## Verification

- Query `GetWatchExperience` and confirm subtitle metadata is present for videos with generated tracks
- Open a watch page with generated subtitles and confirm the player exposes captions controls
- Confirm keyboard users can toggle captions and select a track
- Confirm a watch page without subtitle tracks renders no broken or empty captions UI
- `cd apps/web && pnpm build`

## Success Criteria

- Generated VTT subtitle tracks are reachable from watch-page GraphQL data
- Video sections and video hero sections both support captions consistently
- Subtitle UX is accessible and degrades cleanly when subtitle data is incomplete

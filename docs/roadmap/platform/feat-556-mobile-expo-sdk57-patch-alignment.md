## Problem

The `expo-doctor` CI job fails at `npx expo install --check` on clean `main`.
Expo SDK 57 now expects newer patch versions of seven installed packages, so
unrelated pull requests cannot pass the repository CI gate.

## Entry Points — Read These First

1. `apps/mobile/package.json` — the seven Expo dependency ranges reported by CI.
2. `pnpm-lock.yaml` — lockfile generated by pnpm for the updated ranges.
3. `.github/workflows/ci.yml` — the existing `expo-doctor` job and CI gate.

## Grep These

- `npx expo install --check`
- `expo-doctor@1.20.1`
- `expo-build-properties`

## What To Build

Use Expo's supported installer to align `expo`, `expo-build-properties`,
`expo-glass-effect`, `expo-linking`, `expo-notifications`, `expo-router`, and
`expo-video` with SDK 57 compatibility metadata. Regenerate the pnpm lockfile.

## Constraints

- Stay on Expo SDK 57 and leave React and React Native versions unchanged.
- Preserve the version check and Expo Doctor CI gates.
- Do not change application behavior, native source, or deployment settings.

## Verification

Run frozen install, the Expo version check, CI-isolated Expo Doctor, Mobile
tests, lint, typecheck, and build. Check formatting and lockfile stability,
then require green PR CI before merging through the normal flow.

## Results

The seven direct Expo dependencies now match SDK 57 compatibility metadata.
Frozen install, `npx expo install --check`, the CI-isolated
`expo-doctor@1.20.1`, Mobile lint, typecheck, build, formatting, and the default
Mobile Jest command pass. Jest reports 342 suites and 5,819 tests passing.

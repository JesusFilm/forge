## Problem

`apps/web/src/lib/language-bcp47-map.ts` and `packages/watch-url-policy/src/public-watch-language-slugs.ts`
were both header-commented as "AUTOGENERATED" with a named regeneration command
(`pnpm --filter @forge/web generate:language-bcp47-map`) and a claimed CI drift test
(`apps/web/src/lib/language-bcp47-map.test.ts`), but neither the script nor the drift test exists
anywhere in the repo. Both files were last regenerated by hand on 2026-05-28 and had since drifted from
admin's live `Language` table as `core-sync` keeps moving data — feat-450 found and patched 57 concrete
drift instances (including the named `blang` 404 bug) via manual, one-off live-API verification, which is
not a repeatable process and will drift again.

## Entry Points — Read These First

1. `apps/web/src/lib/language-bcp47-map.ts` — header comment now honestly documents this as a
   hand-maintained snapshot pending this ticket; it no longer references a nonexistent generator.
2. `packages/watch-url-policy/src/public-watch-language-slugs.ts` — same.
3. `apps/web/src/lib/locale.ts` — consumers: `isPublicWatchLanguageSlug()`, `slugToBcp47Tag()`,
   `slugToBcp47Primary()`.
4. `apps/web/src/lib/locale.test.ts` — asserts the two files' keys/slugs agree with each other; keep this
   passing, and consider whether it should also assert against a live/fixture-captured admin snapshot.
5. `docs/roadmap/platform/feat-450-watch-language-allowlist-missing-blang.md` — read its Resolution
   section first: it documents the manual audit method, the sandbox data-access limitations encountered,
   the `hasVideos` unreliability finding, the `lala` duplicate-slug anomaly, and the 21 bcp47 collision
   groups touching the last patch — decide what this generator should do about each.
6. `docs/roadmap/platform/feat-452-language-hasvideos-reliability.md` — a sibling ticket proposing to fix
   `Language.hasVideos` at the source; if that lands first, this generator should consume the corrected
   field directly instead of re-deriving its own inclusion heuristic.

## What To Build

1. A real, runnable generator script (`pnpm --filter @forge/web generate:language-bcp47-map` or
   equivalent) that queries admin's actual `Language` table (Postgres directly, or admin's GraphQL API —
   whichever matches this repo's established data-access pattern for `apps/web` build-time scripts) and
   regenerates both `language-bcp47-map.ts` and `public-watch-language-slugs.ts` deterministically,
   preserving their existing committed shape (sorted, same corpus/map format) so diffs stay reviewable.
2. Decide and document the actual inclusion filter. feat-450 found `hasVideos: true` correlates with, but
   does not exactly match, the corpus that should be admitted — `hasVideos` itself under-reports (`blang`
   has live video content but reads `hasVideos: false`, and is absent from the general paginated
   `languages(offset, limit)` listing entirely, only resolvable via direct-by-id lookup or a video's
   `variantLanguagesWithSlug`). The generator needs a real, verified-correct filter, not the
   listing-plus-`hasVideos` approximation feat-450 used for its manual patch — coordinate with feat-452 if
   that ticket is making `hasVideos` itself reliable.
3. Add or fix the CI drift test the old header comments claimed existed
   (`apps/web/src/lib/language-bcp47-map.test.ts` regenerates and diffs against the committed file) so
   this class of drift is caught automatically instead of discovered as 404s.
4. While rebuilding, resolve two known upstream data anomalies surfaced during feat-450's audit (or
   explicitly punt on them with a documented reason):
   - `lala` — two different admin `Language` ids both slug to `lala` (id `106963`, "Lala (Nigeria)",
     bcp47 `lla`; id `15622`, "Lala (Zambia)", bcp47 `leb`; both `hasVideos: true`). The current map
     silently keeps only one. Decide the correct disambiguation (e.g. suffix one slug) rather than
     silently dropping data.
   - The general paginated `languages(offset, limit)` API listing does not include every language that
     direct-by-id lookup and video-variant data confirm exist and have playable content (`blang` is the
     confirmed example). Confirm why (a default filter on that resolver?) and make sure the generator's
     data source does not inherit the same blind spot — e.g. prefer a query shape that doesn't silently
     drop rows, or paginate a different/lower-level source.

## Constraints

- Do not regress the corpus/map's existing committed format (plain slug-per-line corpus, sorted
  `Record<string, string>` map) without a strong reason — other tooling and this file's own drift test
  will diff against it.
- Keep the generator's output dependency-free at the `packages/watch-url-policy` consumption boundary (per
  that package's existing header comment rationale — every Forge client needs the slug corpus without
  bundling the full BCP-47 value map).
- Any live-data access this script needs (admin Postgres connection or admin GraphQL bearer) must follow
  this repo's existing env-var/credential conventions — do not hardcode credentials or bypass
  `apps/admin`'s established data-access patterns.
- Do not silently drop the `lala`-style duplicate-slug case in the generator's output without an explicit,
  documented disambiguation decision — a generator that reproduces today's silent-drop behavior doesn't
  fix the underlying data-quality gap, it just re-automates it.

## Problem

`/watch/jesus.html/blang.html` 404s because `packages/watch-url-policy/src/public-watch-language-slugs.ts`
(a static allowlist gating `apps/web/src/lib/locale.ts` `isPublicWatchLanguageSlug()`) doesn't
contain `"blang"`. This file and its sibling `apps/web/src/lib/language-bcp47-map.ts` were frozen on
2026-05-28 and never regenerated against admin's live `Language` table, even though admin's data has
kept moving via `core-sync`. The header comments on both files claimed an "AUTOGENERATED" origin with a
named regeneration script and a CI drift test; neither the script nor the drift test exists anywhere in
this repo. This ticket is a manual, individually-verified patch to unblock affected languages now;
rebuilding the real generator + drift test is tracked separately by feat-451.

## Resolution

**blang (the named bug):** Confirmed via the public core GraphQL API
(`https://api-gateway.central.jesusfilm.org/`), `language(id: "139769", idType: databaseId)` returns
`bcp47: "blr"`, `slug: "blang"`. Independently re-confirmed the language has live public video content
by querying the JESUS video (`1_jf-0-0`) `variantLanguagesWithSlug`, which returns
`{ slug: "jesus/blang", language: { id: "139769", bcp47: "blr", slug: "blang" } }`. `blang` reads
`hasVideos: false` both directly and in the general paginated `languages(offset, limit)` listing — it
does not appear in that listing at all, despite being real and playable — so it was validated by direct
ID + video-variant evidence instead of the listing/`hasVideos` heuristic used for the rest of the batch.
Added `blang: "blr"` to `language-bcp47-map.ts` and `blang` to `public-watch-language-slugs.ts`.

**Sandbox data-access constraints:** No `apps/admin` Postgres or local admin GraphQL server was reachable
in this environment (no Doppler project access to `forge-admin`/`forge-web`, no Railway CLI access to the
Forge project, no `.env.local`, no secrets-manager CLI). The public core GraphQL API
(`https://api-gateway.central.jesusfilm.org/`) — the same production data surface `apps/web` traces back
to via `core-sync` — was the only reachable ground truth, and was used directly rather than trusting any
local/stale snapshot.

**Verification methodology:** Paginated the full `languages(offset, limit) { id bcp47 slug hasVideos name }`
listing (2317 entries fetched), then individually cross-checked every candidate slug from this ticket's
original handoff plus a smaller independently-sourced base list against that live snapshot. 56 of the 57
final entries matched cleanly (correct slug, correct bcp47, `hasVideos: true`) directly in the general
listing. `blang` required the direct-by-id + video-variant fallback described above because it is absent
from the general listing despite being real. `Language.hasVideos` itself is known to under-report (blang
is direct proof: live playable content, `hasVideos: false`), so it was used only as a supporting
**positive** signal for the 56, never as a strict gate on its own, and never trusted from a stale/local
snapshot.

**Flagged, not fixed — data-quality notes for feat-451:**

- **bcp47 collision groups:** 21 of the 57 new entries share a bcp47 code with at least one other language
  in the live corpus (macro-language grouping — e.g. several Manobo dialects all map to distinct-but-related
  codes, several Zhuang dialects collide, etc). This is expected/normal in the domain (many real dialects
  share one ISO-639-3/BCP-47 code) and is not a bug in this batch; flagging only because it affects how a
  future generator should reason about bcp47-keyed lookups. Groups touching the 57: `acz`, `ase`, `atd`,
  `axk`, `ayb`, `bjo`, `bkd`, `bru`, `bwx`, `iii`, `mbb`, `mbt`, `msm`, `obo`, `pcc`, `pmf`, `skr`, `ssi`,
  `sur`, `zch`, `zgm`.
- **Duplicate-slug anomaly (`lala`):** two distinct admin `Language` rows both resolve to slug `lala` —
  id `106963` (`Lala (Nigeria)`, bcp47 `lla`, `hasVideos: true`) and id `15622` (`Lala (Zambia)`, bcp47
  `leb`, `hasVideos: true`). This is a pre-existing upstream data issue (not part of this batch's 57,
  already noted as out-of-scope for a quick patch) — the repo currently keeps only one of the two under
  that slug. Left unresolved here; feat-451 should decide the correct disambiguation.
- Re-verified this specific point fresh against live data during this pass: `ralte`, `kwasio`, and `salar`
  (three of the 57) each resolve to exactly one live `Language` row apiece — no duplicate-id anomaly was
  found for any of them. `lala` (unrelated to this batch) is the only duplicate-slug case found in the
  live corpus during this audit.

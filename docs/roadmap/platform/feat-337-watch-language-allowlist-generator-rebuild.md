## Problem

`apps/web/src/lib/language-bcp47-map.ts` and `packages/watch-url-policy/src/public-watch-language-slugs.ts`
are both header-commented as "AUTOGENERATED" with a named regeneration command
(`pnpm --filter @forge/web generate:language-bcp47-map`), but that script does not exist anywhere in the
repo. Both files were last regenerated by hand on 2026-05-28 and have since drifted from admin's live
`Language` table as `core-sync` keeps moving data (feat-336 found and patched 12 concrete drift
instances, including the named `blang` 404 bug, via manual, one-off live-API verification — not a
repeatable process).

## Entry Points

1. `apps/web/src/lib/language-bcp47-map.ts` — header comment names the missing generator script.
2. `packages/watch-url-policy/src/public-watch-language-slugs.ts` — same.
3. `apps/web/src/lib/locale.ts` — consumers: `isPublicWatchLanguageSlug()`, `slugToBcp47Tag()`,
   `slugToBcp47Primary()`.
4. `apps/web/src/lib/locale.test.ts` — comment claims a `apps/web/src/lib/language-bcp47-map.test.ts`
   drift test exists; it does not (stale doc reference — verify/fix as part of this work).
5. `docs/roadmap/platform/feat-336-watch-language-allowlist-missing-blang.md` — feat-336's Resolution
   section documents the manual audit method and its limits; read it first.

## Grep These

- `generate:language-bcp47-map`
- `AUTOGENERATED from admin Language.bcp47`
- `LANGUAGE_BCP47_MAP`
- `PUBLIC_WATCH_LANGUAGE_SLUGS`

## What To Build

1. A real, runnable generator script (`pnpm --filter @forge/web generate:language-bcp47-map` or
   equivalent) that queries admin's actual `Language` table (Postgres directly, or admin's GraphQL API
   — whichever this repo's established data-access pattern for `apps/web` build-time scripts is) and
   regenerates both `language-bcp47-map.ts` and `public-watch-language-slugs.ts` deterministically,
   preserving their existing committed shape (sorted, same corpus/map format) so diffs stay reviewable.
2. Decide and document the actual inclusion filter (feat-336 found `hasVideos: true` correlates with,
   but does not exactly match, the current ~2263-entry corpus size, and `hasVideos` itself under-reports
   — `blang` has live video content but reads `hasVideos: false`). The generator needs a real,
   verified-correct filter, not the approximation feat-336 used for its manual patch.
3. Add or fix the CI drift test the header comments already claim exists
   (`apps/web/src/lib/language-bcp47-map.test.ts` regenerates and diffs against the committed file) so
   this class of drift is caught automatically instead of discovered as 404s.
4. While rebuilding, resolve two known upstream data anomalies surfaced during feat-336's audit (or
   explicitly punt on them with a documented reason):
   - `lala` — two different admin `Language` ids both slug to `lala` (`leb` vs `lla` bcp47); the current
     map silently keeps only one. Decide the correct disambiguation (e.g. suffix one slug) rather than
     silently dropping data.
   - Confirm whether admin-side slug renames/consolidations (feat-336 observed one live id's slug had
     changed since an unrelated stale reference was taken) need any migration/redirect handling for
     previously-public URLs built from the old slug.

## Constraints

- Do not regress the corpus/map's existing committed format (plain slug-per-line corpus, sorted
  `Record<string, string>` map) without a strong reason — other tooling and this file's own drift test
  will diff against it.
- Keep the generator dependency-free at the `packages/watch-url-policy` consumption boundary (per that
  package's existing header comment rationale — every Forge client needs the slug corpus without
  bundling the full BCP-47 value map).
- Any live-data access this script needs (admin Postgres connection or admin GraphQL bearer) must follow
  this repo's existing env-var/credential conventions — do not hardcode credentials or bypass
  `apps/admin`'s established data-access patterns.

## Verification

- Generator runs idempotently: running it twice with no upstream data change produces no diff.
- `pnpm --filter @forge/web test -- src/lib/locale.test.ts`
- New/fixed `apps/web/src/lib/language-bcp47-map.test.ts` (or equivalent) passes and actually fails when
  a stale entry is intentionally introduced (regression-proof the drift check itself).

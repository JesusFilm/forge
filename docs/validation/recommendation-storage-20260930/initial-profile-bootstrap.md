# Initial empty profile bootstrap: future-write validation

The new `RECOMMENDATION_PROFILE_EMPTY_BOOTSTRAP_SKIP` flag defaults to `false` and changes only an ordinary **first** durable projection dispatch. It does not remove a profile, consent receipt, active session link, audit transition, existing generation, or later empty replacement. A successful skip returns the internal `initial_no_evidence` result and creates no run. An evidence-advanced, reconciliation, forced, session, or prior-state dispatch retains the existing path. The public GraphQL response and completed-run contract do not change. No migration or retained rewrite is involved.

## Safety boundary

Under the existing per-scope dispatch transaction advisory lock, the gate requires an active matching profile and initiating session link; no pointer; no retained generation or projection run in any state for that privacy generation; no unexpired selection or playback episode in **any** active linked session after profile/link authorization; and zero durable, session, explicit-preference, and negative-evidence entries from the projector's current loader. The raw-source checks include pending eligibility and missing-embedding sources. Other causes bypass the gate even if the loader is empty. A raw source committed after a status read is not swallowed by a run: the status transaction skips without creating a coalescing row.

An eligible profile-scoped selection or playback outcome atomically reserves the existing `PENDING` projection run in the classifier decision transaction, but only for an active linked scope without prior projection state. This reservation is additive and active even while the skip flag remains off, so both HTTP and worker roles can converge before skip activation. It takes the same per-scope dispatch lock, locks profile/link before writing the eligibility decision, and rechecks validity and prior projection state. A first ordinary run creation performs one no-semantic-change profile-row update; a classifier with an older Serializable snapshot then retries, even when the lock was released before it tried to acquire it. An exact decision replay repairs a missing first reservation. Ordinary post-commit feedback reuses the unstarted reservation even when a later watermark has arrived, provided no generation exists; forced and explicit reconciliation wakes do not reuse it. If the callback or workflow start fails, the existing indexed stale-run reconciler finds the null workflow ID and retries. No run is reserved for unqualified or unlinked sources. Classification that itself never succeeds remains the pre-existing best-effort gap; neither the baseline projector nor this gate can learn an unclassified source.

Native tests cover default-off fallback, absent and lost links, pending raw episode and selection without an embedding, ineligible decision, failed and fenced prior runs, published generation with and without pointer, privacy reset and erasure, both dispatch lock orders and the two stale-Serializable-snapshot interleavings, two distinct eligible classifiers sharing one first scope, real retention closure holding profile/outcome/eligibility authority during a later eligible decision revision, late watermark reservation reuse, first qualified upgrade, exact eligible decision replay repair, failed workflow start followed by reconciliation discovery, and retained projection/candidate behavior. Existing profile-service and reconciliation tests cover later empty replacement and privacy fences. The gate is deliberately conservative: declared-empty production generations are an upper bound on opportunities, because raw pending sources may disqualify them.

## Local allocation and latency fixture

On the task-owned local PostgreSQL database, two fresh schemas received identical 100,000 active profiles, 100,000 grant audits, 25,000 session links, and 20,000 unrelated pending playback episodes. The baseline schema additionally received 100,000 published empty durable generations, completed projection runs, and pointers. The skip schema retained their empty indexes but no rows. Both used the current recommendation migration chain. Sizes were measured after inserts and before dispatch timing; schemas were dropped afterward. The temporary timing script used Prisma's legacy datasource engine; the later native concurrency and recovery suite uses the production `PrismaPg` adapter with an explicit schema/search path. This synthetic fixture models relation allocation and index cardinality, not a production forecast.

| Scope                                                | Skip bytes | Baseline bytes | Avoided bytes |
| ---------------------------------------------------- | ---------: | -------------: | ------------: |
| Core profile + link + audit, including indexes/TOAST | 72,335,360 |     72,335,360 |             0 |
| Generation, run, pointer, including indexes/TOAST    |    180,224 |    205,103,104 |   204,922,880 |
| Total six relations                                  | 72,515,584 |    277,438,464 |   204,922,880 |

The avoided allocation is 103,669,760 heap bytes, 101,163,008 index bytes, and 90,112 TOAST bytes, after subtracting the empty relation allocations. The measured write WAL was 177,819,992 bytes for the skip schema versus 522,324,128 bytes for baseline, a 344,504,136-byte difference. **This allocation fixture predates the later first-run row-version fence**, so its WAL comparison does not include that added write. WAL counters are cluster-global interval measurements; this was a quiet local window, but checkpoint/full-page-write timing can change the value. Workflow engine rows were not included in the physical fixture, so whole-system savings are not proved or forecast here.

`EXPLAIN (ANALYZE, BUFFERS)` of the raw selection/episode absence query against the 100,000-profile fixture took 0.129 ms. It used `recommendation_profile_session_generation_key`, `recommendation_request_session_created_idx`, `recommendation_selection_attribution_idx`, `recommendation_episode_session_created_idx`, and `recommendation_playback_episode_expires_at_idx`; no full source scan appeared. The projector evidence loader still runs after this query, so end-to-end dispatch costs more.

For 100 sequential first-empty calls on linked scopes, gate ON p50/p95 was 9.98/30.98 ms; 100 repeated gate-ON calls p95 was 11.60 ms. Gate OFF first-run creation on other untouched scopes p95 was 7.11 ms. A separate set with already completed initial runs and pointers (coalesced path) had p95 3.38 ms. Ten batches of eight concurrent distinct empty scopes had gate-ON batch p95 112.09 ms versus existing completed/coalesced path 38.47 ms. These are local process-to-DB timings, not HTTP production latency or an equivalent baseline for the first path. The repeated empty-status tax is material and must be checked under production-like request load before enabling the flag.

A second quiet local fixture with 100,000 profiles, 25,000 links, 20,000 unrelated pending episodes, and 200 real finalized outcome sources measured the **unconditional preparatory classifier change** with skip still off, also using the legacy datasource engine. Across 100 sequential first eligible classifications, process-to-DB p50/p95 was 28.01/43.79 ms; across 100 already-projected eligible classifications, 23.82/27.21 ms. The reservation helper alone measured p95 6.82 ms for untouched linked scopes and 3.78 ms for already-projected scopes using its pointer fast return. These are different scopes, not a paired before/after classifier benchmark, and do not isolate an incremental classifier p95. A separate 1,000-row self-update of the profile fence wrote 787,816 bytes of global-interval WAL and grew the relation by 278,528 bytes in that fresh fixture. The update changes no profile timestamp or privacy value, runs only on first durable run creation, and adds no write to a successful empty skip. Its allocation may be reclaimed through normal tuple cleanup; it is not deducted from the initial six-relation saving above. Repeat loaded latency with the actual `PrismaPg`/HTTP path before activation.

## Activation and rollback

Keep the skip flag `false` in the preparatory release. The unconditional eligible-source reservation is additive; verify both HTTP and worker roles run the new reservation and first-run fence before any skip activation. After fleet convergence, independently validate raw-source and projection-run aggregate shapes, dispatch error rate, DB pool wait, repeated empty-status p95, feedback-to-first-real-projection lag, and first-empty materialization rate. Verify the effective HTTP and worker flag values, including explicit deployment overrides. Enable skip in a later normal PR and monitor a bounded pilot; setting the flag back to `false` immediately restores initial dispatch creation for future calls. Skipped scopes have no new retained format and remain readable by prior images. A rollback image must retain the reservation/fence behavior during the pilot and understand every pre-existing profile projection format already deployed. Do not delete retained empty generations or rewrite history as part of this feature.

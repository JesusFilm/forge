# Playback QA and Feedback Loop for Manager App

## Problem Frame

The manager app can deep-link to Mux, but it does not provide a real QA loop around the final viewing experience. Operators cannot inspect autoplay caption behavior, compare delivery targets, capture viewer quality signals, or connect those signals back to the enrichment pipeline. If captions or voiceover feel wrong, the current system learns about it too late or not at all.

## Requirements

- R1. Add an in-app playback QA surface to video/job detail in the manager app.
- R2. The default player experience prioritizes autogenerated captions when that is the only available subtitle track, matching the intuitive behavior users expect from modern players.
- R3. Operators can switch between available outputs such as Mux playback, downloadable artifacts, YouTube delivery, and voiceover variants from one control surface.
- R4. After a user watches with captions enabled for roughly two minutes, the system prompts for a lightweight quality signal: good or bad, with an optional reason.
- R5. Feedback events store the video, language, active track, timestamp, playback target, and viewer response so quality can be reviewed later.
- R6. Manager users can see aggregate quality trends for captions, translations, and voiceovers and jump directly to the affected moment/output.
- R7. Download actions for Mux-ready or generated assets are available from the same playback QA surface.

## Success Criteria

- Caption and voiceover quality issues are captured from actual viewing behavior instead of guesswork.
- Operators can test the output experience without leaving the manager app.
- Feedback data is actionable enough to trigger retraining, reruns, or human review.

## Scope Boundaries

- Not a full analytics suite for all viewer behavior.
- Not an always-on survey; prompts are conditional and low-friction.
- Not a custom video CDN or transcoding system.

## Key Decisions

- Playback QA lives next to job/video detail because quality review is part of operations, not a separate analytics product.
- The feedback prompt is tied to caption usage, not generic watch time, because the problem to solve is output quality.
- Mux remains the default reference player, with alternative players treated as comparison targets.

## Dependencies / Assumptions

- Mux playback IDs remain the canonical primary output for first-pass QA.
- Additional player targets such as YouTube or voiceover streams can be integrated incrementally behind the same selector model.

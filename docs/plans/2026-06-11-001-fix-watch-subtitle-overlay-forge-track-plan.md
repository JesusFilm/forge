# fix: Restrict Watch Subtitle Overlay to Forge-Selected Tracks

## Summary

The Watch subtitle overlay should render only subtitle tracks selected through Forge's subtitles modal. Mux-native generated tracks may still exist on the media element, but they must not leak into the React overlay unless Forge injected that exact subtitle track.

---

## Problem Frame

`watch/jesus.html/english.html` has no selectable English subtitle option in the Forge subtitles modal, yet the player can still show English captions because Mux advertises a generated English HLS subtitle group. Forge's modal is sourced from admin `VideoEdition.subtitles`, while `SubtitleOverlay` currently reads any active media `subtitles` or `captions` track. That makes Mux-generated tracks visible outside the modal's state model.

This plan is a narrow bug fix under `feat-177`, carrying the admin-backed subtitle control requirements from `docs/brainstorms/2026-05-25-web-video-subtitle-controls-requirements.md` and the broader generated subtitle UX context from `docs/roadmap/media-generation/feat-035-video-palyer-ux-for-autogenerated-subs.md`.

---

## Requirements

**Overlay authority**

- R1. `SubtitleOverlay` renders cue text only from the Forge-injected subtitle track selected through `WatchPageClient` and `LanguagePickerModal`.
- R2. Mux-native or Mux-generated subtitle/caption tracks, including tracks labeled `Generated subtitles`, remain ignored by the Forge overlay even when their mode is `showing` or `hidden`.
- R3. Turning subtitles off through the modal still removes or disables the Forge-injected track and clears overlay text.

**Compatibility**

- R4. The fix preserves existing Mux metadata, thumbnail, and chapter tracks.
- R5. The fix works for both `MuxPlayer` and `MuxVideo` hero branches because both expose media `textTracks`.
- R6. No GraphQL schema, payload, or subtitle modal option behavior changes in this bug slice.

---

## Key Technical Decisions

- KTD1. Match the Forge track by a shared internal label: `HeroPlayer` already labels injected tracks `__forge_subtitle__`; `SubtitleOverlay` should use the same constant so overlay eligibility follows the injection path instead of generic text-track state.
- KTD2. Keep built-in track disabling in `HeroPlayer`: disabling non-Forge tracks remains useful defense, but overlay correctness should not depend on Mux never reactivating a native track later.
- KTD3. Test `SubtitleOverlay` directly: the bug is in overlay track selection, so a small jsdom media/text-track harness gives stronger coverage than a broad hero-player render that depends on mocked Mux internals.

---

## Scope Boundaries

In scope:

- Add a shared Watch subtitle-track label helper or constant.
- Update `SubtitleOverlay` to filter to the Forge-injected track.
- Update `HeroPlayer` to use the shared constant instead of duplicating the string literal.
- Add focused unit coverage for native/generated track ignore behavior and Forge-track cue rendering.

Out of scope:

- Adding or backfilling English subtitles in admin.
- Surfacing Mux-generated tracks as selectable modal options.
- Changing subtitle preference cookies, language routing, GraphQL fragments, or admin sync.
- Redesigning player chrome or modal layout.

## Implementation Units

### U1. Share the Forge subtitle-track identifier

- **Goal:** Make the internal Forge subtitle track label a single source of truth.
- **Requirements:** R1, R5
- **Files:**
  - Create `apps/web/src/components/watch/subtitle-track.ts`
  - Modify `apps/web/src/components/watch/HeroPlayer.tsx`
  - Modify `apps/web/src/components/watch/SubtitleOverlay.tsx`
- **Approach:** Export `FORGE_SUBTITLE_TRACK_LABEL = "__forge_subtitle__"` from a small watch-local helper. Replace the duplicated literal in `HeroPlayer` and use it in `SubtitleOverlay`.
- **Patterns to follow:** `apps/web/src/lib/watch-player-chrome-events.ts` for small watch-local shared constants; `apps/web/src/components/watch/HeroPlayer.tsx` for the existing injection path.
- **Test scenarios:** Existing HeroPlayer tests should continue to pass with no behavior change.
- **Verification:** TypeScript import paths remain client-safe and do not introduce server-only dependencies.

### U2. Restrict overlay track selection

- **Goal:** Prevent Mux-native/generated subtitle tracks from feeding `SubtitleOverlay`.
- **Requirements:** R1, R2, R3, R4
- **Files:**
  - Modify `apps/web/src/components/watch/SubtitleOverlay.tsx`
  - Create `apps/web/src/components/watch/__tests__/SubtitleOverlay.test.tsx`
- **Approach:** In `findSubtitleTrack`, require `t.label === FORGE_SUBTITLE_TRACK_LABEL` in addition to `kind` and active mode checks. Keep the existing `mode = "hidden"` transition for the Forge track so the React overlay can render cues without browser-native captions. If no Forge track is active, detach any previous cue listener and clear `cueText`.
- **Patterns to follow:** Existing cue listener lifecycle in `SubtitleOverlay`; colocated watch component tests under `apps/web/src/components/watch/__tests__/`.
- **Test scenarios:**
  - A Mux-generated subtitle track with `mode: "showing"` does not render overlay text.
  - A Forge-labeled subtitle track with active cues renders overlay text after playback is committed.
  - Switching from a Forge track back to only native/generated tracks clears the overlay.
- **Verification:** `pnpm --filter @forge/web test -- src/components/watch/__tests__/SubtitleOverlay.test.tsx`

### U3. Focused regression validation

- **Goal:** Prove the narrow fix does not regress the existing Watch hero subtitle/player path.
- **Requirements:** R1, R3, R5, R6
- **Files:**
  - Modify tests only if U1/U2 exposes an existing assumption.
- **Approach:** Run the new overlay test plus the existing hero-player test suite. Use browser smoke against the Watch page to confirm the overlay no longer renders generated English captions unless a Forge subtitle is active.
- **Patterns to follow:** `docs/solutions/design-patterns/watch-language-player-chrome-layout-20260609.md` for Watch player verification expectations.
- **Test scenarios:** Existing `HeroPlayer` behavior remains stable; modal-driven subtitle activation still injects a Forge-labeled track.
- **Verification:**
  - `pnpm --filter @forge/web test -- src/components/watch/__tests__/SubtitleOverlay.test.tsx src/components/watch/__tests__/HeroPlayer.test.tsx`
  - Browser smoke on `watch/jesus.html/english.html`

---

## Risks & Dependencies

- Mux can add native subtitle tracks after initial metadata load. Filtering in `SubtitleOverlay` is required even when `HeroPlayer` disables built-in tracks on `addtrack`.
- jsdom does not implement real `TextTrackList` behavior. The test harness should provide the minimal event and cue API that `SubtitleOverlay` reads without mocking the component logic under test.
- A saved subtitle preference can make a Forge track active in a real browser. Browser proof should distinguish Forge-selected tracks from Mux-native generated tracks by inspecting track labels.

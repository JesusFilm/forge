# 02: Request and retrieve an exact draft render

**Parent:** [Specification](../spec.md) · planning tracker feat-541

**Status:** approved; published as `feat-543` with `ready-for-agent` readiness.

**What to build:** The connected agent requests a render of its current draft, checks progress after reconnecting, and retrieves scoped media access plus a human link to the exact output. Use existing footage without generated narration to prove this independently.

**Blocked by:** 01 — Connect an external agent and edit the correct project.

## Acceptance criteria

- [ ] A narrowly authorized delegated request admits a render for an exact revision through the existing durable rendering service without impersonating a human reviewer.
- [ ] Admission returns a durable attempt identity promptly; queued/running/succeeded/failed/stale outcomes remain readable across client disconnection.
- [ ] Exact retries do not enqueue another render. Changed request bodies cannot reuse an accepted idempotency key.
- [ ] Canonical capture and source materialization complete through the trusted broker; arbitrary fetch URLs and unverified media/code do not bypass existing containment.
- [ ] An operator can open the returned project/revision/render link and watch the exact generated bytes; a later project edit labels earlier output stale for approval.
- [ ] Output byte access is short-lived and scoped; expired access can be refreshed through authentication without storing bearer URLs in project history.
- [ ] Existing concurrency, execution timeout, cancellation/recovery, and immutable completion rules remain enforced. The tool grants no approval or publishing authority.

## Test boundary

MCP request/status/read against canonical lifecycle and the contained render worker; loss/retry/stale-result cases.

# Next development preview requests reading a production manifest

The custom programmatic Manager preview launcher returned HTTP 500 for `/login`
and authenticated editor requests, looking for
`.next/dev/required-server-files.json`. An unauthenticated editor request returned
307, masking the broken destination. Next route modules select production
manifest loading when their development context is absent; the manifest is
normally generated by builds, not development startup.

Recovered by replacing the ad hoc launcher with the installed `next dev` CLI,
regenerating the local dev cache, and preserving the existing tunnel/auth callback
origin. Do not fabricate a production manifest in the dev cache. The precise
trigger for loss of development context in the former process was not established.

Manager `next.config.ts` allows the configured `MANAGER_BASE_URL` hostname only in
development so tunnel fonts and HMR continue to load under the standard CLI.
The preview launcher must load its private environment before invoking the CLI.
Do not print that environment or bypass normal authentication for verification.

Verify the full redirect chain (`curl -L`), not only the editor's initial 307.
Also verify tunneled fonts return 200 and HMR connects. Browser verification
reached the expected Auth sign-in page; authenticated content requires sign-in.

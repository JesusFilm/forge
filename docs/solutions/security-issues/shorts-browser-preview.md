# Browser preview without a separate service

The editor loads a fixed Remotion/compiler bundle lazily and embeds it in a
`srcdoc` iframe with `sandbox="allow-scripts"`. Generated component source is sent
as message data and evaluated only inside that opaque frame. CSP permits canonical
Mux/Core media and local blobs; Manager network/script origins, parent DOM,
cookies, forms, popups and top navigation are unavailable. This is browser
isolation, not the VM's CPU/memory containment guarantee.

`shorts-browser-preview.ts` checks current canonical source eligibility and returns
HLS URLs without downloading or transcoding video. Audio/images and referenced
component code are digest-read with byte limits, passed to the frame, and converted
to local blob URLs. Only active components are loaded. Text-only compositions need
no preview API call. Editing and seeking send messages without restaging media.
Removing the frame releases its media; no server preview session exists to renew.

`render-prepare` retains the former broker's source codec verification and signed
manifest materialization. The render panel saves changed references and uses the
resulting revision for admission. Edits arriving during preparation stop that
submission; save failures do not queue a render. Existing render-input proof
checks and disposable VM execution remain enforced.

Builds and development generate `public/shorts-preview/runtime.js`; generated bytes
are ignored by git. Deployment follows the normal Manager PR build. The old
preview app can remain stopped; no provisioning is required. Keep
`STUDIO_PREVIEW_API_KEY` for existing render-source proof compatibility. Its name
is historical, and editing no longer requires it or the old preview origin/URL.

## Verification

- Manager production build and typecheck passed with inert build-only provider values.
- Focused preview/editor/render tests and the 69 composition tests passed.
- Actual browser fixture using the changed Preview component: Mux HLS and uploaded
  music both reached readyState 4 and advanced; seek to 30 seconds and live text
  edits worked. Custom TSX rendered while parent DOM, cookie and Manager fetch
  attempts were blocked. No preview service was running.
- Six alternating text-only component loads: old median ready 344 ms, new 387 ms;
  old median DOMContentLoaded 97 ms, new 90 ms. New parent fixture +198 gzip bytes.
  Both load the same framework lazily. Old iframe requests are not included in
  parent-only Resource Timing byte totals. This local fixture excludes the old
  broker/staging delay and does not prove full-page or production speedup. The
  initial baseline fixture lacked CORS; corrected before the six comparison loads.

No raw traces, captures, generated bundles or media are committed.

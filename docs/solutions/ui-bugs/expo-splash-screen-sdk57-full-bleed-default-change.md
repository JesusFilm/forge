# Silent splash-screen regression on Expo SDK 54→57 upgrade

## Problem

The SDK 54→57 upgrade changed the native splash screen without any code
change to the splash image or its `app.json` config.

On SDK 54, `expo-splash-screen` rendered the configured `splash-icon.png`
full-bleed on cold launch. After the SDK 57 upgrade and a fresh prebuild,
the same image renders as a small centered logo, about 100pt, on the
background color. The `app.json` `image`, `resizeMode`, and
`backgroundColor` values did not change. Only the generated native splash
artifact changed, because the plugin's default rendering style changed
between SDK versions.

## Symptoms

- Cold launch shows a small centered logo instead of a full-bleed image.
- The regression is visible only by watching an actual cold launch. It
  does not show in any log, lint, or test output.
- `apps/mobile/app.json` is unchanged before the regression appears; a
  diff of the app.json plugin block shows no drift.

## What Didn't Work

Nothing in the normal upgrade checklist caught this. Each of these ran
clean, and each looked like a valid signal that the upgrade was safe:

- **`app.json` diff.** The `expo-splash-screen` plugin config block was
  byte-for-byte identical before and after the SDK bump. A textual diff
  of the source config gives no signal, because the regression lives in
  the plugin's DEFAULT interpretation of that config, not in the config
  itself.
- **`expo-doctor`.** Ran clean. `expo-doctor` checks package version
  compatibility and known misconfigurations. It has no check for a
  visual change in generated splash output.
- **CI.** CI never inspects prebuild output. The native splash screen is
  generated by the config plugin during `expo prebuild` from a
  storyboard/XML template. No test in the suite renders or diffs that
  generated artifact.
- **TypeScript and unit tests.** All pass. The regression has no
  TypeScript surface and no unit-testable behavior; it is a rendering
  default inside a native storyboard.

## Solution

Add `enableFullScreenImage_legacy: true` to the `expo-splash-screen`
plugin entry in `apps/mobile/app.json`. Current state on this branch
(`apps/mobile/app.json`, plugin entry, matches PR #1926):

```json
[
  "expo-splash-screen",
  {
    "image": "./assets/splash-icon.png",
    "resizeMode": "contain",
    "backgroundColor": "#1c1917",
    "enableFullScreenImage_legacy": true
  }
]
```

The fix landed on this branch in the commit that carries the subject
`fix(mobile): apply review findings 2 and 4 (splash parity, real-shape
fixture)`. Its `apps/mobile/app.json` hunk:

```diff
         {
           "image": "./assets/splash-icon.png",
           "resizeMode": "contain",
-          "backgroundColor": "#1c1917"
+          "backgroundColor": "#1c1917",
+          "enableFullScreenImage_legacy": true
         }
       ],
       "expo-status-bar"
```

That SHA will be rewritten when PR #1926 squash-merges, so treat the PR,
not the SHA, as the durable anchor for this fix.

Verification at the time of the fix: the regenerated iOS storyboard
(image asset `SplashScreenLegacy` in `SplashScreen.storyboard`) constrains the image to all four edges, confirming
full-bleed layout, not the centered-logo layout.

## Why This Works

`expo-splash-screen@57.0.6` changed its default rendering mode. With no
`enableFullScreenImage_legacy` flag, the plugin treats the configured
`image` as a small centered logo mark on top of `backgroundColor`, sized
around 100pt. `enableFullScreenImage_legacy: true` tells the plugin to
generate the older, full-bleed layout instead, where the image fills the
screen subject to `resizeMode`.

The flag name is explicit about its role: it is a legacy escape hatch.
Expo's own default moved to the logo style on purpose, as a design
decision for SDK 57, not as a regression in the plugin. Setting the flag
opts this app back into the SDK 54 look without pinning an older plugin
version.

## Prevention

On any Expo SDK major upgrade, treat config plugins as capable of
changing default behavior for unchanged config. A clean `app.json` diff
proves the _input_ config did not change. It does not prove the
_generated native output_ did not change.

- **Diff generated native artifacts, not just `app.json`.** Run `expo
prebuild --clean` before and after the upgrade and diff the generated
  iOS storyboard / Android splash XML, not only the source config files.
- **Visually compare cold-launch frames.** Record or screenshot the
  first frame of a cold launch before and after the upgrade. Config
  plugin defaults render natively; no build error or lint warning marks
  a visual default change.
- **Grep upgrade changelogs for `_legacy` flags.** A newly introduced
  `_legacy`-suffixed option in a plugin's changelog is a direct signal
  that the plugin's default behavior changed and that the flag exists
  specifically to restore the old default. Search the SDK upgrade notes
  and each touched plugin's own changelog for `_legacy` before trusting
  a green `expo-doctor` and a clean `app.json` diff.
- **Do not treat `expo-doctor` or CI as covering native visual output.**
  Both operate above the generated-artifact layer. Neither renders or
  diffs the actual native splash/launch screen.
